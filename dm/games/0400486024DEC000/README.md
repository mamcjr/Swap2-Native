# The Legend of Zelda: Ocarina of Time (`0400486024DEC000`)

A Switch 2 game: update v131072 over the base v65536, SDK 22.2.8 built for the Switch 2 (`Ounce`). Nintendo EPD's engine (sead / agl / gsys, Phive, RSDB, ELink2 / SLink2, Havok 2025.2) on NVN2, modules `main`, `subsdk0` and `sdk`. **Provisional profile, reaches the title screen**: brought up on Android in Swap2-Native (2026-11-05; POCO F7 Ultra, Adreno 830). Lichii (an Eden-based Switch 2 emulator) calls it "the green-hat kid adventure" ([Lichii build 75](https://github.com/zortos293/Lichii/releases/tag/build-75), [its PR 87](https://github.com/zortos293/Lichii/pull/87)).

## What it needs

Implemented, gameplay validation pending (2026-11-09): [Android image-cache ownership under RAM pressure](../../../docs/reference/memory.md#android-image-cache-ownership-under-ram-pressure). Production ownership tests passed on Android; matched gameplay memory improvement remains unmeasured.

Follow-up implementation (2026-11-09): application-pool enforcement is now the general default, and this profile uses BananaNative's verified 8 GiB alias layout. Existing registered Android packs receive a memory-only metadata migration before launch; shaders and code stay intact. [Allocation-burst cache checks](../../../docs/reference/memory.md#android-allocation-bursts-bypass-a-frame-only-image-cache-check) and [pool-accounting validation](../../../docs/reference/memory.md#maps-past-the-application-pool-fail-as-on-horizon) address the additional comparison findings. [Release/device validation](../../../docs/BUILD-0.1.3-beta-MEMORY-POLICY-2026-11-09.md) distinguishes unit checks from gameplay outcomes.

Subsequent native copy crash: [CPU re-upload lifetime](../../../docs/reference/memory.md#cpu-texture-re-uploads-do-not-refresh-image-lifetime) was missing from pressure-eviction tracking; corrected for full/partial/sparse transfers. ARM64 production-code tests pass. [Crash evidence and remaining GPU validation](../../../docs/BUILD-0.1.3-beta-TRANSFER-LIFETIME-2026-11-09.md) remain separate from proof of stable gameplay.

Current, 2026-11-09: public 0.1.2-beta still has Android LOW_MEMORY exits before reliable gameplay. The latest recorded process PSS was about 7.5 GB. Read-only device evidence, the missing finalized-pool eviction/cache-policy integration, shader-library freshness and the host implementation/validation plan are in Zelda RAM investigation (`ANALISE-ZELDA-RAM-2026-11-09.md`, kept local). No memory fix or same-device BananaNative A/B result is claimed by that investigation.

- [Image cache limit blind to swap](../../../docs/reference/memory.md#image-cache-limit-blind-to-swap-android): entering Castle Town on the POCO F7 Ultra (16 GB, 891.14) the game fell to 0.1-0.5 fps for minutes, 5.9 GiB of the process in swap, 13,000 major faults a second, images 2.0-2.5 GiB at a limit MemAvailable (held up by zram) kept above them, PSI not readable (2026-11-24). Current: the faults stand in for PSI, and the profile's low-RAM keys (`low_ram_place_part_mb 64`, `low_ram_img_cache_max_mb 1280`, from Banana Native) apply on 12 GiB or less, as upstream. On the 16 GB POCO the 1280 MiB ceiling made Castle Town slower (about 12 fps, 1651 prunes of textures in use) than without it (about 14.5 fps, GPU-bound; 0.2.0.1 with RAM saving 16-18 fps at another spot), so it no longer applies there; an eviction that spares textures used in recent frames is open.
