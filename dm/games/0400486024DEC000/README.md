# The Legend of Zelda: Ocarina of Time (`0400486024DEC000`)

A Switch 2 game: update v131072 over the base v65536, SDK 22.2.8 built for the Switch 2 (`Ounce`). Nintendo EPD's engine (sead / agl / gsys, Phive, RSDB, ELink2 / SLink2, Havok 2025.2) on NVN2, modules `main`, `subsdk0` and `sdk`. **Provisional profile, reaches the title screen**: brought up on Android in Swap2-Native (2026-11-05; POCO F7 Ultra, Adreno 830). Lichii (an Eden-based Switch 2 emulator) calls it "the green-hat kid adventure" ([Lichii build 75](https://github.com/zortos293/Lichii/releases/tag/build-75), [its PR 87](https://github.com/zortos293/Lichii/pull/87)).

## What it needs

Implemented, gameplay validation pending (2026-11-09): [Android image-cache ownership under RAM pressure](../../../docs/reference/memory.md#android-image-cache-ownership-under-ram-pressure). Production ownership tests passed on Android; matched gameplay memory improvement remains unmeasured.

Follow-up implementation (2026-11-09): application-pool enforcement is now the general default, and this profile uses BananaNative's verified 8 GiB alias layout. Existing registered Android packs receive a memory-only metadata migration before launch; shaders and code stay intact. [Allocation-burst cache checks](../../../docs/reference/memory.md#android-allocation-bursts-bypass-a-frame-only-image-cache-check) and [pool-accounting validation](../../../docs/reference/memory.md#maps-past-the-application-pool-fail-as-on-horizon) address the additional comparison findings. [Release/device validation](../../../docs/BUILD-0.1.3-beta-MEMORY-POLICY-2026-11-09.md) distinguishes unit checks from gameplay outcomes.

Subsequent native copy crash: [CPU re-upload lifetime](../../../docs/reference/memory.md#cpu-texture-re-uploads-do-not-refresh-image-lifetime) was missing from pressure-eviction tracking; corrected for full/partial/sparse transfers. ARM64 production-code tests pass. [Crash evidence and remaining GPU validation](../../../docs/BUILD-0.1.3-beta-TRANSFER-LIFETIME-2026-11-09.md) remain separate from proof of stable gameplay.

Current, 2026-11-09: public 0.1.2-beta still has Android LOW_MEMORY exits before reliable gameplay. The latest recorded process PSS was about 7.5 GB. Read-only device evidence, the missing finalized-pool eviction/cache-policy integration, shader-library freshness and the host implementation/validation plan are in Zelda RAM investigation (`ANALISE-ZELDA-RAM-2026-11-09.md`, kept local). No memory fix or same-device BananaNative A/B result is claimed by that investigation.

## Found on this game

- [Adreno shared memory advertised past 32 KiB](../../../docs/reference/shaders.md#adreno-shared-memory-advertised-past-32-kib): Turnip Gen8 V39 advertises 64 KiB of compute shared memory on the Adreno 830, which has 32 KiB; a 64 KiB workgroup reads its upper half wrong and overwrites its start (measured 2026-11-20). The host takes at most 32 KiB on Qualcomm GPUs since then, so the task/mesh packing no longer goes past it on V39. Current: the host change is checked on the phone (2026-11-20, V39: 32768 used); whether this was the night tests' foliage defect is open.
- [A Qualcomm custom driver silently falls back on Android 15](../../../docs/reference/rendering.md#a-qualcomm-custom-driver-silently-falls-back-on-android-15): upstream Banana Native found 891.14 falling back to the system driver on an Odin 3 (Android 15) because the driver's namespace lacked an API 36 Binder function; ported 2026-11-17 as `libbinder_compat_hook.so`, loaded for a custom driver on API < 36 only. Current, not checked here (open: a run on an Android 15 phone; the POCO F7 Ultra is Android 16 and is unaffected).
- [Atomics at an unaligned address on a core without FEAT_LSE2](../../../docs/reference/rewriter.md#atomics-at-an-unaligned-address-on-a-core-without-feat_lse2-android): upstream Banana Native v0.3.40 found the game's `ldadd` on an odd address (`main+0x104e4c`) killing it on a Snapdragon 888 (their issue #343); ported 2026-11-17, done in software in the crash handler on Android arm64. Current, not checked here (open: a run on an Armv8.2 phone).
- [Android pipelines that kill the driver while it compiles them](../../../docs/reference/shaders.md#android-pipelines-that-kill-the-driver-while-it-compiles-them): DroidPlay Core found Qualcomm's compiler on an Adreno 735 (V@0762) crashing on the game's first compute pipeline `a039399e6336de1b` at every start, a short build the 2 s rule of `.deadly` never kept; ported 2026-11-17: the crashing thread's build is listed at any length, and the list is kept per driver and host build. Current, unit-tested only (open: a `DM_VK_PIPE_CRASH` run on the phone).
- [Timestamp reports carried to a later signal read the completion time](../../../docs/reference/frame-rate.md#timestamp-reports-carried-to-a-later-signal-read-the-completion-time-on-the-vulkan-replay): upstream Banana Native v0.3.14 found its dynamic resolution reading 0 ms of GPU time with the GPU waits on; ported 2026-11-13, and the profile now sets `gpu_timestamps segment` (as upstream's).
